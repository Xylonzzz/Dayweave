# 账户、自动登录与阿里云升级

## 注册与个人空间

0.1.5 在「我的账户」增加昵称、头像、学校、专业和简介。资料保存在个人空间偏好中，随 JSON 备份及手动同步迁移；昵称沿用原来的称呼，登录用户名不变。头像在浏览器内裁成 256×256 图片后保存，不支持 SVG 或外部图片链接。

「版本与更新」显示页面版本，独立窗口另外显示安装程序版本。检查 GitHub 最新正式 Release；没有 Release 时查询 main 的源码版本，并明确提示没有可下载的安装包。检查仅获取信息，下载与安装由用户操作。断网或 GitHub 无法访问时显示失败原因，个人资料和本地使用不受影响。

新版 Windows 安装程序启动独立空间时，会自动升级与发行原版完全一致的源码，并保留旧源码恢复副本；数据文件夹不移动。已被 AI 或手动修改的源码保持原样，因此页面版本与桌面窗口版本可能不同。该机制支持已知原版 0.1.4 及此后带源码清单的版本。

登录页支持创建账户，默认凭邀请码注册。原来由 `ADMIN_USER` 创建的账号自动成为服务器管理员；原有用户名、密码、课程、任务、AI 配置和对话保留在原位置。

管理员进入「偏好与 AI 设置 → 我的账户 → 注册与邀请设置」，可以查看、更换邀请码，关闭注册或开启公开注册。朋友打开服务器网址，选择「创建个人账户」，填写用户名、密码和邀请码即可。

每个账户分别保存课程、任务、日程、灵感、复盘、AI 密钥、对话、通知订阅和恢复点。AI 接口需要每个人自行添加；共享服务器不等于共享 API 配额。服务器管理员仍能通过服务器和数据库访问数据，这不是端到端加密。

登录页的「自动登录（30 天）」使用 HttpOnly Cookie，不保存明文密码。不勾选时使用浏览器会话 Cookie，服务端最长 8 小时；勾选时最长 30 天。浏览器的恢复会话功能可能保留会话 Cookie，需要立即退出时使用「退出此账户」。修改密码会撤销本人的所有登录和同步授权，不影响其他账户。旧版本已存在的登录按原有效期迁移。

本地离线空间仍属于当前浏览器，不自动按云端账户拆分。同一服务器地址改连另一个账户时，必须移除旧同步连接并重新预览；程序会检测不同个人空间的标识，阻止沿用原来的合并历史。多个账户同时使用建议各自使用独立的浏览器配置或设备。

## 当前阿里云 SQLite 容器升级

适用于已有 `dayweave` 容器、`/app/data` 命名数据卷、回环端口 3088 和外部 Nginx HTTPS 代理的安装。脚本不修改 Nginx 或 HTTPS 续签任务。

在服务器终端逐行执行：

```bash
cd /opt/dayweave
git pull --ff-only
bash deploy/update-cloud.sh --accounts
```

`cd` 是进入源码目录，`git pull` 是下载更新，最后一行构建并启动新版本。构建期间旧服务继续运行，切换容器时会短暂中断。脚本保存原容器配置、SQLite 在线快照和 `secret.key` 到 `/opt/dayweave-backups/日期时间`；新版本健康检查失败时会重新启动旧容器。业务数据卷不会删除，旧容器保留但停止自动重启。

SQLite 备份包含所有账户及聊天；Harness 的额外原始日志仍留在原数据卷中，不属于此次数据库快照。备份目录包含密钥及运行配置，只允许服务器管理员读取。新版本启动失败后回退旧程序不等于还原数据库快照；新增用户只能在支持多账户的版本使用。

## 再启用 Harness

先确认注册、独立空间和普通 API 均可正常使用。内存充足的构建机器可以执行：

```bash
bash deploy/update-cloud.sh --harness
```

这次构建固定提交 `47f943859bef60e4160492346772ded9b24f765a`、版本 `0.1.0-rc.5` 的 Harness，并在容器内配置 `/opt/harness`。不需要手机或每位朋友另装 Node、Docker、Harness，也不需要开放新端口。基础镜像使用之前可访问的 AWS 官方公开镜像库；其余下载仍需要 Debian、GitHub 和 npm 可访问。

完成后每位用户在「AI 接口」里配置自己的 OpenAI Chat Completions 兼容接口，在「AI 时间管家」中选择 DeepSeek Harness。支持日程查询、修改、公开网页搜索和阅读。各账户的 Harness 会话目录分开保存，原管理员沿用原路径。

普通用户不能通过源码定制工作台修改整台服务器的程序。该部署继续保留 `SHIXU_DEVELOPMENT=disabled`；部署聊天 Harness 不会自动开放源码开发权限。

Harness 构建比普通版本消耗更多内存、磁盘和下载流量。实际测试在 1.5 GB JavaScript 堆上限发生编译内存不足，构建配置因此使用 4 GB 堆上限；升级脚本会阻止在总内存不足 6 GB 的机器直接编译。当前 2 GB 阿里云服务器使用下面的预构建方式，不需要因此迁移现有数据库。构建失败时脚本不会停止正在运行的旧服务。

预构建的方式：在另一台机器运行 `docker build -f deploy/Dockerfile.harness -t dayweave:harness .` 和 `docker save -o dayweave-harness.tar dayweave:harness`，把归档上传服务器后运行 `docker load -i dayweave-harness.tar`，然后执行 `DAYWEAVE_IMAGE=dayweave:harness bash deploy/update-cloud.sh --harness`。这样云端只加载并运行，不负责大型构建。

## 开源部署与兼容性

账户目录和会话绑定保存在现有 KV 表，无需删除 SQLite 数据或改变 MySQL 5.7 表结构。现有管理员的同步标识保持不变，新用户使用独立空间标识；新用户需要支持多账户的新版本同步客户端。

未实现邮件验证、忘记密码自助重置、管理员删除账户，以及每账户独立源码版本。管理员邀请设置是本阶段的账户管理入口。
