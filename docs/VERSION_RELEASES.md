# 候选版本试运行与切换

在本机通过桌面开关或 `node launcher.mjs` 启动时序，再进入「定制我的工具」。开发完成后保留候选版本，按以下顺序操作：

1. 点击「启动试运行」。程序检查候选文件是否仍与测试、审查时一致，将版本单独保存。
2. 点击「打开试运行版本」，使用页面显示的测试账号、密码登录。试运行有独立地址和空白数据，不复制正式账号、日程、聊天或 API 密钥。页面顶部有试运行提示。
3. 试用满意后，勾选确认，点击「切换使用此版本」。正式页面会短暂断开，稍后刷新；版本状态会显示成功或失败原因。
4. 如需撤回，在「运行版本」勾选恢复，再点击「恢复上一个版本」。恢复代码时保留最新业务数据。

试运行需要 Docker；正常运行已发布版本只需要现有 Node 环境，不要求 Docker 持续运行。试运行容器 30 分钟后自动停止，也可手动停止。试运行内新建的测试数据不会转入正式空间。公网和远程发布暂不开放。

## 本阶段支持范围

当前允许主页面脚本、外观脚本、样式、HTML 和静态资源等前端改动切换。已有共享模块、后端、依赖和执行控制程序必须保持相同；不符合时明确拒绝切换，可继续在隔离空间试运行。这是本阶段对版本兼容性的保守约束，不代表所有 AI 改动都可以自动上线。

数据库迁移、聊天格式变化、服务器接口变化及依赖升级需后续单独设计迁移与恢复协议。此阶段的恢复只恢复代码，不能当作数据库降级或恢复旧日程。

## 保存与恢复机制

- `.shixu-releases/` 保存独立版本、校验值、预览信息和运行指针；`.shixu-development/` 保留原有任务及审查记录。它们不进入 Git。
- 版本管理进程独立于候选代码。切换前先检查校验值、当前源码是否发生后续变化、兼容范围及试运行记录；停止旧服务后调用 SQLite 一致性备份，再启动候选版本。
- 健康检查核对新进程的启动标识、数据库连接及主页面脚本响应。启动失败会重新启动旧版本，不把失败版本记为当前版本。启动检查不等同于所有业务功能正确。
- 运行指针在新版本通过检查后才更新。进程意外终止后，通过桌面开关重新启动时会加载记录版本；若启动失败且存在前一版本，则尝试恢复，并显示结果。
- 恢复旧版本也会先备份最新数据。所有兼容版本使用同一正式数据目录，因此恢复代码不会清除切换期间新增的日程。
- 试运行候选容器只有只读源码和临时数据，处于内部网络。可信转发入口只指向该容器，绑定本机端口；使用每次独立的 `.localhost` 地址和预览 Cookie，过滤正式登录 Cookie。转发入口不挂载源码或业务数据。

旧的 `node server.mjs` 启动和源码整合仍保留，但不具备运行版本切换。使用启动器管理时，页面会锁定为「保留候选版本」，并以运行版本恢复替代直接覆盖源码。关闭旧服务后重新运行桌面开关即可启用管理模式。

已发布版本使用独立源码目录。开发者直接编辑项目根目录不会自动覆盖已启用版本；新的 AI 定制会基于实际运行版本创建副本。上游升级与用户定制合并仍待后续实现。

## 验证

`npm test` 覆盖候选被修改时拒绝发布、后端变化拒绝切换、独立进程切换、启动失败恢复、恢复代码后保留最新数据。Edge 页面测试覆盖试运行入口、发布与恢复勾选、手机布局。

`node tests/release-smoke.mjs` 需要已准备的 Docker 镜像与 Edge。它复制项目到独立测试目录，使用人工构造的已审查候选，实际启动容器和浏览器，再用独立正式服务验证切换和恢复。该夹具不是一次真实 AI 开发或审查的证明，也不读取正式日程、账号或 API 配置。

2026-10-03：使用 DeepSeek V4 Pro 完成“待提交作业”筛选功能，记录 `6814d6c6-e71c-44e1-a102-f11ed08def06`。只改动 `public/app.js`；模型实际测试、宿主回归和独立审查通过。运行 `node tests/release-smoke.mjs --real-ai`，真实 Edge 在容器预览和切换后的独立正式服务中验证：仅显示已完成但未提交的作业；其他作业状态及已完成项目不进入该筛选。随后调用实际恢复接口，确认旧代码恢复、后续新增数据保留。截图和记录保存在 `test-output/`；未切换用户个人空间。
