# Windows 桌面测试版

## 独立窗口安装版

运行 `npm run build:installer` 生成 `Shixu-Setup-版本号.exe`。下载这个安装 EXE、双击安装，桌面出现「时序独立窗口」，进入 Electron 原生窗口中的时序，不需要另外打开浏览器。`dist/latest-installer.json` 记录最新产物。

安装版自带窗口运行环境和 Node。首次启动优先连接原版 3088 服务；没有原服务时，可创建桌面独立空间或先导入完整备份。按 Alt 显示菜单，「时序」中可切换空间、复制桌面空间首次登录信息、打开数据目录或停止桌面后台。

0.1.1 起，点击关闭按钮会收起到系统托盘，程序仍运行；点击托盘图标恢复，右键可退出并停止桌面独立服务（不停止原版 3088）。仅关闭窗口不等于退出。电脑休眠或关机后不能继续运行；现有自动同步仍遵循前台页面规则，托盘模式没有改变同步协议。标题栏跟随页面明暗配色，普通菜单默认收起。

「偏好与 AI 设置 → 外观与主题」支持主/辅双色、三组撞色预设和日期卡片独立文字/背景颜色。所有颜色选择器带代码输入框，支持 `#RRGGBB`、`#RGB`、`rgb(r,g,b)`，兼容 `0#FFFFFF`。无效输入不会覆盖上次有效颜色。取消日期自定义后，日期卡片恢复跟随浅色/夜间模式。

新图标以圆角松绿底、钟环与琥珀圆点组成。矢量源为 `public/app-icon.svg`；`node desktop/render-icon.mjs` 生成 PNG 和 ICO。

0.1.2 去掉品牌图标外框和自定义标题栏分隔线。外观设置与灵感气泡各自支持纯色、磨砂、玻璃、亚克力、云母和纸感六种材质，独立保存在本设备；气泡颜色、透明度与 3D 设置仍然保留。材质由应用内 CSS 渲染，不读取桌面壁纸，不是 Windows 原生系统背景材质；不支持背景模糊时界面回退到清晰的纯色底。

0.1.3 将顶部工具栏背景与左右留白统一，新增整体背景色（HEX/RGB）和完整主题预设。取消「使用自定义背景色」可恢复跟随明暗模式。可选松林晨光、午夜星云、紫藤薄雾、暖砂手札，也可命名保存当前外观（最多 20 套）及删除自定义预设；切换主题不会修改独立的气泡设置或业务数据。

服务端数据与定制代码继续保存在 `%LOCALAPPDATA%\Shixu`，沿用原桌面空间。Electron 的 Cookie 和离线 IndexedDB 属于独立窗口自己的浏览器空间，不会自动读取 Edge 的离线数据；需要在旧入口导出，再在新窗口导入。服务器登录需要重新进行。安装新版本不自动覆盖现有定制 workspace。升级或卸载前，先用菜单停止桌面后台服务并关闭窗口；卸载保留个人数据。

窗口启用沙箱和上下文隔离，网页不能直接使用 Node；HTTPS 服务器切换仍在设置中进行。同步、AI 接口和权限边界沿用原应用。本机测试不等同于干净电脑或阿里云上线验收；当前安装包没有代码签名。

构建前需 `npm ci`（允许 Electron 官方下载脚本），并有一次 `npm run build:windows` 产物，供复用 Node 与生产依赖。`build:installer` 将最新允许源码覆盖到独立打包目录，生产依赖变化时要求先重新构建基础包。验证入口 `node tests/window-smoke.mjs`；用 `SHIXU_WINDOW_EXE` 指向安装后的 EXE 可验证真实安装版。测试只使用独立临时账号和数据。

## 旧版浏览器启动器

第一版为 Windows x64 原生 EXE 启动器，打开现有浏览器中的时序界面。随包提供 Node 运行环境、npm 与应用依赖，不需要用户另外安装 Node；日常使用不需要 Docker。AI 定制仍在工作台按需准备 Docker、WSL 和 Harness。

## 使用

解压完整文件夹，双击「时序.exe」。请保留旁边的 `app`、`runtime`、`desktop` 文件夹，不能只复制 EXE。可以为 EXE 创建桌面快捷方式。

也可以双击 `Install.cmd`，安装到当前用户的 `%LOCALAPPDATA%\Programs\Shixu\构建编号`，自动创建桌面与开始菜单的「时序 (Installed)」快捷方式，无需管理员权限。安装前逐文件检查 SHA-256，复制后再次检查；损坏的包不会建立入口。初次校验和复制可能需要数分钟，请等窗口显示 Installed。

新构建安装在独立目录，快捷方式切换到新启动器，旧程序保留。同一构建不重复覆盖安装；异常中断会报告未完成目录。安装器更新启动器与随包环境，**不自动更新已存在的 workspace，也不合并用户定制**。

卸载时先在启动器停止桌面后台服务，再关闭启动器，双击对应程序文件夹中的 `Uninstall.cmd`。它只删除该构建中内容未变的随包文件，以及仍指向该构建的快捷方式；额外文件、被改过的文件、其他构建及 `%LOCALAPPDATA%\Shixu` 下全部个人数据与定制代码保留。浏览器离线数据也保留。当前不注册 Windows 设置中的应用卸载项。

- 检测到原版 `localhost:3088` 时，默认打开原服务和原数据。
- 独立桌面空间使用 `localhost:3090`。首次打开启动器会先显示选择，允许先导入备份，再启动；也可点击「打开时序」创建空白空间。
- 新建空白空间后，用「复制首次登录信息」获取账号密码；导入备份则使用原账号密码。
- 关闭启动器窗口后，日程服务继续在后台运行。「停止桌面后台服务」只停止它自己的桌面空间，不能停止原版或其他服务。
- 电脑重启后，再次双击 EXE。当前没有添加开机自启。

## 文件与升级

程序包与个人数据分离：默认使用 `%LOCALAPPDATA%\Shixu\workspace` 保存可定制代码，`%LOCALAPPDATA%\Shixu\data` 保存数据库和运行日志。首次启动复制源码和依赖；以后复用该空间，重新解压新安装包不会自动覆盖用户定制。

运行版本、环境准备和 AI 开发记录仍保存在 workspace 内各自的隐藏目录。已准备工具可复用，前端候选的发布与恢复保持原有流程。此版没有自动合并官方升级或自动更新功能。

## 迁移

先在原版创建完整备份（`npm run backup:local`），在首次创建桌面空间前，用「首次导入旧版完整备份」选择同时包含 `planner.sqlite` 和 `secret.key` 的文件夹。通过一致性检查后复制到新空间，不移动或删除原数据；目标已有数据时拒绝覆盖。

完整服务端备份包括账号、聊天和 API 配置，但不包括浏览器 IndexedDB。原网址中的离线空间，需要在那里导出 JSON，再到新网址的本地空间预览导入。两个网址的浏览器数据不会自动互通。

## 构建与验收

开发者在 Windows x64、Node 24 与现有 .NET Framework 编译器环境下运行 `npm run build:windows`。构建使用固定 package-lock 安装生产依赖，保留依赖许可证并附 Node 许可证；只打包允许的源码，不包括 `.env`、业务数据、开发记录或下载缓存。

构建还会自动生成包含 UTF-8 中文文件名的 ZIP、对应 `.sha256` 和包内 `package-manifest.json`。`dist/latest.json` 指向本次产物。哈希用于检查传输损坏，不等同于发布者签名。

测试入口：`npm test` 验证隔离、迁移和保留定制；`node tests/desktop-smoke.mjs` 使用打包后的 Node、独立账号和数据，清除 PATH 中的系统 Node，验证登录、版本管理与重启后数据保留。EXE 另有 `--self-test 报告路径` 的诊断入口，应设置独立 `SHIXU_DESKTOP_HOME`，不能用于个人正式空间。

当前为未签名的本地测试包；不是单文件安装器。全新电脑、不同 DPI 与系统版本、完整首次 WSL/Docker 安装链路仍待实机验证，不把本机测试视为这些环节已经通过。
